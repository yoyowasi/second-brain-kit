## 1. 세컨드 브레인이란

머리 밖에 두는 기억 장치다. 떠오른 것과 알아낸 것을 적어 두고, 필요할 때 다시 찾고, 서로 연결해 새 생각이나 결과물로 다시 쓴다. 기억하려고 애쓰는 대신 "어디에 적어 두었는지"만 알면 되게 만드는 것이 목표다.

이 키트는 두 가지 방법을 섞는다.

- **PARA**: Tiago Forte가 정리한 분류법으로, 노트를 Projects(끝나는 일), Areas(계속 관리하는 영역), Resources(참고 자료), Archive(보관) 네 갈래로 나눈다.
- **영구 노트**: 읽고 겪은 것에서 다시 쓸 생각 하나를 골라 내 말로 다시 쓴 짧은 노트다. Zettelkasten(사회학자 니클라스 루만의 메모 방식)에서 온 개념이다.

여기에 분류 전 메모를 모으는 **인박스**와 하루를 기록하는 **일일 노트**를 더했다. 노트는 Obsidian으로 보고 쓰지만 실제로는 내 컴퓨터 폴더에 있는 평범한 Markdown(`.md`) 파일이다. 그래서 AI 에이전트도 같은 파일을 직접 읽고 쓸 수 있다.

## 2. 준비물 설치

### 2-1. 프로그램 설치

| 준비물 | 왜 필요한가 | 어디서 | 확인 방법 |
|---|---|---|---|
| Obsidian | 노트를 보고 쓰는 앱 | [obsidian.md](https://obsidian.md) | 앱이 열린다 |
| Python 3.9 이상 | 보조 도구 `sb.py` 실행 | [python.org](https://www.python.org/downloads/) | 아래 명령 |
| Claude Code 또는 Codex | 말로 부탁하는 AI 에이전트 | 각 공식 문서([Claude Code](https://code.claude.com/docs/en/overview), [Codex](https://github.com/openai/codex)) | 터미널에서 실행된다 |
| Git(선택) | 이 키트 내려받기, 볼트 백업 | [git-scm.com](https://git-scm.com) | `git --version` |

설치 방법은 각 공식 사이트의 안내를 따른다. 이 문서에서는 설치 단계를 따로 적지 않는다(버전마다 바뀐다).

Python 확인:

```powershell
# Windows (PowerShell)
python --version
```

```bash
# macOS / Linux
python3 --version
```

`Python 3.9` 이상이 나오면 된다. 이 문서의 bash 예시는 `python3`로 적었다. Windows의 Git Bash에서 bash 예시를 따라 할 때는 `python3`가 실행되지 않을 수 있으니 `python3` 대신 `python`을 쓴다. Windows에서 `python`을 입력했는데 Microsoft Store가 열리거나 "찾을 수 없다"고 나오면 아직 설치가 안 됐거나 PATH에 등록되지 않은 것이다. python.org 설치 프로그램으로 설치할 때 PATH에 추가하는 옵션을 켠다. python.org 설치에 함께 들어가는 `py` 명령(`py --version`)으로 대신 실행해도 된다.

AI 에이전트 없이도 볼트는 쓸 수 있다. 그때는 `sb.py`를 직접 실행하고 Obsidian에서 손으로 정리하면 된다.

### 2-2. 이 키트 설치

**무엇을 하나**: 이 저장소를 내려받고, `second-brain` 스킬을 AI 에이전트의 스킬 폴더에 복사한다. Claude Code에는 세션 일지·규칙 제안을 남기는 자동 기록(hook)과 `/inbox`·`/init-project` 스킬도 함께 설치한다([자동 기록](AI와-함께-쓰기.md#자동-기록-claude-code-hook)). Codex를 쓰면 Codex 세션도 기본으로 같은 세션 일지에 들어간다(끄는 법: [Codex 세션](AI와-함께-쓰기.md#codex-세션)).
**왜**: 스타터 볼트와 보조 도구 `sb.py`가 스킬 폴더 안에 함께 들어 있어서, 볼트를 만들기 전에 먼저 설치해야 한다.

1. 저장소를 내려받는다. Git이 있으면 `git clone <저장소 주소>`, 없으면 저장소 페이지에서 ZIP으로 내려받아 압축을 푼다.
   - `git clone`은 명령을 실행한 폴더 아래에 저장소 이름의 폴더를 만든다.
   - ZIP은 압축을 푼 위치에 폴더가 생긴다. 폴더 이름 끝에 `-main` 같은 브랜치 이름이 붙거나, 같은 이름의 폴더가 한 번 더 들어 있을 수 있다.
2. 터미널에서 저장소 폴더로 이동한다. `<저장소 폴더>`는 1에서 생긴 폴더의 경로로 바꾼다. `ls`로 `install.ps1`, `install.sh`, `README.md`가 보이면 맞는 폴더다(PowerShell에서도 `ls`가 된다).
3. 설치 스크립트를 실행한다.

```powershell
# Windows (PowerShell)
cd "<저장소 폴더>"
ls
powershell -ExecutionPolicy Bypass -File install.ps1          # Claude Code용
powershell -ExecutionPolicy Bypass -File install.ps1 -Codex   # Codex에도 설치
powershell -ExecutionPolicy Bypass -File install.ps1 -Antigravity   # Antigravity에도 설치
powershell -ExecutionPolicy Bypass -File install.ps1 -All     # Claude Code·Codex·Antigravity 모두
```

```bash
# macOS / Linux
cd "<저장소 폴더>"
ls
bash install.sh           # Claude Code용
bash install.sh --codex   # Codex에도 설치
bash install.sh --antigravity   # Antigravity에도 설치
bash install.sh --all     # Claude Code·Codex·Antigravity 모두
```

`-ExecutionPolicy Bypass`는 그 한 번의 실행에만 적용되고 PC의 실행 정책 설정은 바꾸지 않는다. Codex(`~/.agents/skills`)·Antigravity(`~/.gemini/config/skills`)에는 `second-brain` 스킬만 복사하고, hook·`/inbox`·`/init-project`·`settings.json`·`CLAUDE.md` 변경은 Claude Code에만 한다. Antigravity 스킬 폴더는 Windows에서 Antigravity 내장 `migrate-workflows` 스킬 문서(전역 스킬 위치 `~/.gemini/config/skills/<이름>/SKILL.md`)로 확인했다. 설치 스크립트의 자동 시험은 Windows에서만 돌려 확인했다(CI 없음, macOS·Linux 분기는 자동 시험하지 않음).

**확인**: 끝에 `Installed: ...\.claude\skills\second-brain` 같은 줄이 나오고(Codex 옵션을 줬다면 `...\.agents\skills\second-brain`, Antigravity 옵션을 줬다면 `...\.gemini\config\skills\second-brain`도), 그 폴더에 `SKILL.md`, `scripts/sb.py`, `assets/starter-vault/`가 있다. 이어서 hook 파일·`/inbox`·`/init-project`의 `Installed:` 줄과 `settings.json:`·`CLAUDE.md:` 줄(`만듦`·`갱신`·`변경 없음`)이 나온다. 마지막 `Next:` 줄은 3단계에서 실행할 명령이다(`install.sh`는 `python3`가 실행되지 않는 환경에서 `python`으로 보여 준다). 자동 기록이 세션을 요약하려면 터미널에서 `claude auth login`을 한 번 해 둔다.

## 3. 볼트 만들기

볼트(vault)는 Obsidian이 노트 묶음으로 여는 폴더 하나다. 아래 두 방법 중 하나만 하면 된다.

**왜 Obsidian을 열기 전에 만드나**: 템플릿 파일에는 날짜·제목을 자동으로 채우는 Templater 구문(`<% ... %>`)이 들어 있다. Templater의 "새 파일 생성 시 실행"이 켜진 볼트를 Obsidian이 열고 있는 동안 이런 파일을 넣으면 구문이 그 자리에서 실행되어 `undefined` 같은 값으로 바뀐다. 볼트 파일을 먼저 다 만들고 나서 Obsidian으로 열면 이 문제가 생기지 않는다.

### 방법 1. AI에게 부탁하기

1. 터미널에서 Claude Code(또는 Codex)를 실행한다. 어느 폴더에서 실행해도 된다.
2. "세컨드 브레인 만들어줘"라고 말한다.
3. AI가 만들 위치를 묻는다(기본 제안 `~/Documents/SecondBrain`). 원하는 위치를 답한다. Windows라면 아래 방법 2의 "경로 고르기"처럼 짧은 경로(예: `C:\Notes\SecondBrain`)를 답하는 것이 좋다.
4. AI가 `sb.py init` 실행 허락을 구하면 명령을 확인하고 허용한다.

**확인**: AI가 "볼트를 만들었습니다: <경로>"를 알려 주고 이어서 할 Obsidian 설정을 안내한다.

### 방법 2. 직접 실행하기

```powershell
# Windows (PowerShell)
python "$HOME\.claude\skills\second-brain\scripts\sb.py" init "C:\Notes\SecondBrain"
```

```bash
# macOS / Linux (Windows Git Bash에서는 python3 대신 python)
python3 ~/.claude/skills/second-brain/scripts/sb.py init ~/Documents/SecondBrain
```

**경로 고르기(Windows)**: 짧은 경로를 권한다(예: `C:\Notes\SecondBrain`). Windows는 전체 경로가 260자를 넘으면 파일을 만들지 못할 수 있고, 그러면 `init`이 `볼트를 만들지 못했습니다: ...`와 함께 더 짧은 폴더를 쓰라는 안내를 출력하고 멈춘다. '문서' 폴더를 OneDrive로 옮겨 둔 PC도 주의한다. `$HOME\Documents`가 탐색기의 "문서"와 다른 위치일 수 있고, OneDrive 아래 경로는 길어지기 쉽다. 어느 경우든 아래 출력의 첫 줄에 나온 전체 경로가 볼트 위치다.

이렇게 나오면 성공이다.

```text
볼트를 만들었습니다: C:\Notes\SecondBrain
다음: Obsidian에서 '폴더를 보관소로 열기'로 이 폴더를 열고, Dataview·Templater 플러그인을 켜세요.
      (Templater 템플릿 폴더: 99_System/Templates)
```

첫 줄 아래에 `주의: 환경변수 SECOND_BRAIN(<경로>)이 설정되어 있어 그쪽 볼트가 계속 쓰입니다.`가 함께 나오면, 볼트는 만들어졌지만 AI와 `sb.py`는 환경변수가 가리키는 다른 볼트를 계속 쓴다. 새 볼트를 쓰려면 환경변수를 지운다([AI와 함께 쓰기 > 환경변수 SECOND_BRAIN](AI와-함께-쓰기.md#환경변수-second_brain)).

`init`이 하는 일:

- 기본 폴더(`00_Inbox`부터 `99_System/Routines`까지)를 만든다. 상위 폴더(예: `C:\Notes`)가 없으면 함께 만든다.
- 스타터 볼트(`AGENTS.md`, `Home.md`, 영역 노트, 템플릿, 루틴 프롬프트, 연습용 메모)를 복사한다.
- 볼트 경로를 `~/.second-brain/config.json`에 저장한다. Claude Code와 Codex 설치가 이 설정을 함께 쓰므로 한 번만 하면 된다.
- 이미 `.md` 노트가 있는 폴더에는 아무것도 하지 않고 멈춘다(덮어쓰지 않는다). 그 폴더를 그대로 쓰려면 `init` 대신 `setup`을 쓴다.

**확인**: 경로가 제대로 저장됐는지 본다.

```powershell
# Windows (PowerShell)
python "$HOME\.claude\skills\second-brain\scripts\sb.py" where
```

```bash
# macOS / Linux (Windows Git Bash에서는 python3 대신 python)
python3 ~/.claude/skills/second-brain/scripts/sb.py where
```

`vault:`에 만든 폴더가, `agents_md: ... exists=True`가 나오면 된다. `config:` 줄은 볼트 경로가 저장된 설정 파일(`~/.second-brain/config.json`)이다.

## 4. Obsidian 설정

Obsidian 메뉴 이름은 앱 버전과 언어 설정에 따라 조금씩 다를 수 있다. 아래에는 기능과 함께 이름을 적었다.

### 4-1. 폴더를 보관소로 열기

- **무엇을**: Obsidian 시작 화면에서 "폴더를 보관소로 열기"(Open folder as vault)를 골라 3단계에서 만든 폴더를 연다. 앱 버전에 따라 이름이 다를 수 있다. 폴더 선택 창에서는 `init`이 출력한 전체 경로(`볼트를 만들었습니다: ...`, AI에게 부탁했다면 AI가 알려 준 경로)를 따라가 찾는다. 경로를 잊었다면 `sb.py where`의 `vault:`를 본다.
- **왜**: 이 폴더 자체를 볼트로 열어야 `Home.md`의 목록과 링크가 맞게 동작한다. 상위 폴더를 열면 목록 경로가 어긋난다.
- **확인**: 왼쪽 파일 목록에 `00_Inbox`부터 `99_System`까지 폴더와 `AGENTS.md`, `Home.md`가 보인다.

### 4-2. 커뮤니티 플러그인 Dataview·Templater 설치와 켜기

- **무엇을**: 설정의 커뮤니티 플러그인 화면에서 커뮤니티 플러그인 사용을 허용(제한 모드 끄기)하고, 플러그인 찾아보기에서 **Dataview**와 **Templater**를 검색해 설치한 뒤 각각 켠다(활성화).
- **왜**: Dataview는 `Home.md`와 영역 노트의 "인박스", "진행 중 프로젝트", "열린 할 일" 같은 목록을 자동으로 만든다. Templater는 Obsidian에서 새 노트를 만들 때 템플릿의 날짜·제목을 채운다.
- **확인**: `Home.md`를 열었을 때 `dataview` 코드 블록 대신 목록이 보인다(아직 해당 노트가 없으면 빈 목록이 정상이다).

### 4-3. Templater 설정

- **템플릿 폴더**: Templater 설정의 템플릿 폴더 위치(Template folder location)를 `99_System/Templates`로 정한다.
- **(선택) 새 파일 생성 시 실행**: "Trigger Templater on new file creation"을 켜면 Obsidian에서 새 노트를 만들 때 Templater 구문이 바로 실행된다. 여기서 갈림길이 있다.
  - **Obsidian의 일일 노트 버튼도 쓰려면**: 이 옵션을 켜고 4-4를 한다. 버튼으로 만든 노트에 날짜가 채워지려면 이 옵션이 필요하다.
  - **일일 노트를 AI나 `sb.py`로만 만들려면**: 이 옵션을 끄고 4-4는 건너뛴다. `sb.py`는 값을 채운 뒤 파일을 쓰므로 이 옵션이 필요 없다.
- **주의**: 이 옵션을 켰다면 Obsidian이 열려 있는 동안 Templater 구문이 든 파일을 밖에서 복사해 넣지 않는다. 템플릿 폴더 밖 노트에는 Templater 구문을 쓰지 않는다.

플러그인 설정 이름은 Templater 버전에 따라 다를 수 있다. 자세한 내용은 [Templater 문서](https://silentvoid13.github.io/Templater/)를 본다.

### 4-4. (선택, 4-3 옵션을 켠 경우) 핵심 플러그인 '일일 노트'

- **무엇을**: 설정의 핵심 플러그인에서 "일일 노트"(Daily notes)를 켜고 옵션을 다음처럼 정한다.

  | 옵션(기능) | 값 |
  |---|---|
  | 날짜 형식 | `YYYY-MM-DD` |
  | 새 파일 위치 | `10_Daily` |
  | 템플릿 파일 위치 | `99_System/Templates/Daily` |

- **왜**: Obsidian에서 버튼 하나로 오늘 노트를 열고, AI가 만드는 일일 노트(`10_Daily/YYYY-MM-DD.md`)와 같은 이름·위치·형식을 쓰게 한다.
- **확인**: 왼쪽 리본의 오늘 일일 노트 열기 버튼이나 명령 팔레트(Ctrl+P, macOS는 Cmd+P)에서 "일일 노트"를 검색해 실행한다. `10_Daily/오늘날짜.md`가 열리고, 제목과 `← 어제:` 링크에 날짜가 채워져 있으면 된다. `<% ... %>`가 그대로 보이면 4-3의 "새 파일 생성 시 실행"이 꺼진 것이다. 옵션을 켜고 그 노트를 고친다(8장 "템플릿이나 노트에 `undefined`…" 끝부분).

### 4-5. (선택) Git 플러그인으로 private 백업

- **무엇을**: 커뮤니티 플러그인 **Git**(예전 이름 Obsidian Git)을 설치하고, 볼트 폴더를 **private** 원격 저장소에 연결한다. 연결 방법은 플러그인 문서를 따른다.
- **왜**: 노트 변경 이력이 남고 다른 기기로 옮기기 쉽다.
- **반드시 지킬 것**: 저장소는 private으로 만든다. git으로 올리면 쓴 내용이 그대로 원격으로 나가므로 노트에 비밀번호·토큰·API 키를 쓰지 않는다. 볼트를 이 키트 저장소(공개) 안에 두지 않는다.
- **확인**: 원격 저장소 페이지에서 저장소가 private으로 표시되고, 노트가 올라가 있다.

### 4-6. (선택) 수정 시각 자동 기록 플러그인

- **무엇을**: "Update time on edit"처럼 노트를 고칠 때 frontmatter의 `updated`를 자동으로 적는 플러그인을 설치한다.
- **왜**: AI는 `updated`를 직접 쓰지 않는다. 고친 시각은 플러그인이 맡는 것이 정확하다.
- **권장 설정**(플러그인마다 설정 이름이 다를 수 있다): 수정 시각 키 `updated`, 만든 시각 키 `created`, 날짜 형식은 `created`와 같은 `YYYY-MM-DDTHH:mm` 모양(Update time on edit에서는 `yyyy-MM-dd'T'HH:mm`), 무시할 폴더에 `99_System/Templates`.
- **확인**: 아무 노트나 고치고 저장하면 frontmatter에 `updated: 2026-10-15T09:30` 같은 줄이 생긴다.

## 5. 폴더 구조와 '어디에 둘까'

| 폴더 | 넣는 것 |
|---|---|
| `00_Inbox/` | 분류 전 메모. 일단 여기에 적는다 |
| `10_Daily/` | 일일 노트(`YYYY-MM-DD.md`), `Weekly/`에 주간 리뷰(`YYYY-Www.md`) |
| `20_Projects/` | 끝나는 날이나 완료 조건이 있는 일 |
| `30_Areas/` | 계속 관리하는 책임 영역(업무, 학습, 건강, 재무)과 `나의 판단 방식` |
| `40_Resources/` | `해결 기록/`(해결한 문제), `참고 자료/`(주제별 자료) |
| `50_Notes/` | 내 말로 쓴 생각 하나짜리 영구 노트 |
| `90_Archive/` | 끝난 프로젝트, 더 쓰지 않는 노트 |
| `99_System/` | `Templates/`(노트 틀), `Routines/`(예약 실행용 프롬프트) |

어디에 둘지 헷갈리면 위에서부터 차례로 묻는다.

1. **끝나는 날이나 완료 조건이 있나?** → `20_Projects/`
2. **계속 관리하는 책임인가?** → `30_Areas/`의 영역 노트에 연결한다
3. **나중에 찾아볼 자료인가?** → `40_Resources/`(해결한 문제면 `해결 기록/`, 그 밖에는 `참고 자료/`)
4. **내 생각을 한 문장 주장으로 쓸 수 있나?** → `50_Notes/`

넷 다 아니거나 모르겠으면 `00_Inbox/`에 그대로 둔다. 나중에 "인박스 정리해줘"로 함께 정리하면 된다. 전체 분류 규칙은 볼트의 `AGENTS.md` "분류 질문"에 있다.

## 6. 첫날 해 볼 것과 하루·한 주 리듬

### 첫날 해 볼 것 5가지

1. **오늘 노트 만들기**: AI에게 "오늘 노트 만들어줘"라고 한다(4-4를 설정했다면 Obsidian의 일일 노트 버튼도 된다). → `10_Daily/오늘날짜.md`가 생긴다.
2. **메모 하나 남기기**: "메모해 둬: 다음 주에 읽을 책 목록 정리"처럼 말한다. → `00_Inbox/`에 새 노트가 생긴다.
3. **인박스 정리 연습**: 스타터 볼트에 들어 있는 `00_Inbox/처음 써 보는 메모.md`를 두고 "인박스 정리해줘"라고 한다. → AI가 메모를 나눠 옮기고 "원래 이름 → 위치" 표로 보고한다. 여러 노트로 나누거나 기존 노트에 합친 원본 메모는 지우지 않고 `90_Archive/`로 옮긴다.
4. **진행 중인 일 하나를 프로젝트로**: "볼트에 '블로그 이전' 프로젝트 만들어줘"처럼 말한다. 요청에 '볼트'를 넣어야 AI가 코드 프로젝트가 아니라 볼트의 프로젝트 노트로 알아듣는다. AI가 목표·완료 조건과 영역을 채우거나 물어본다. 영역은 frontmatter에 따옴표까지 포함해 `area: "[[업무]]"`처럼 적는다(따옴표가 없으면 YAML이 링크가 아니라 목록으로 읽는다). 따옴표 없이 적으면 `sb.py lint`가 `frontmatter 'area'의 [[링크]]에 따옴표 필요`로 알려 준다. → `20_Projects/블로그 이전.md`가 생기고 `Home.md`의 "진행 중 프로젝트"에 보인다.
5. **나의 판단 방식 훑어보기**: `30_Areas/나의 판단 방식.md`의 예시 원칙을 읽고 나와 맞지 않는 것을 고친다(7장).

다 했으면 볼트를 점검해 본다. 형식·깨진 링크·남은 Templater 구문·비밀정보로 보이는 문자열을 찾아 준다.

```powershell
# Windows (PowerShell)
python "$HOME\.claude\skills\second-brain\scripts\sb.py" lint
```

```bash
# macOS / Linux (Windows Git Bash에서는 python3 대신 python)
python3 ~/.claude/skills/second-brain/scripts/sb.py lint
```

마지막 줄에 `점검(볼트 전체) N개, 문제 0건`이 나오면 깨끗하다. 파일을 지정해 `lint "<파일 경로>"`로 실행하면 `점검(지정한 파일) N개, ...`로 나온다. 새로 만든 노트가 아직 아무 노트와도 연결되지 않았으면 "고아 노트"로 알려 준다(예: `area`를 비워 둔 프로젝트). 관련 영역이나 프로젝트를 `[[링크]]`로 이어 주면 사라진다. 날짜 링크(`[[2026-10-14]]`)는 일일·주간 노트 안에서는 아직 없는 날짜를 가리켜도 문제로 세지 않지만, 다른 노트에 쓰면 그 날짜의 일일 노트가 없을 때 깨진 링크로 나온다.

### 하루·한 주 리듬

| 언제 | 할 일 | 이렇게 부탁한다 |
|---|---|---|
| 아침 | 오늘 노트를 열고 오늘 집중할 것과 할 일을 적는다 | "오늘 노트 만들어줘" |
| 틈틈이 | 떠오른 것은 분류하지 말고 인박스에 던진다 | "메모해 둬: ○○" |
| 문제를 해결했을 때 | 같은 문제를 다시 만나면 꺼내 쓰도록 기록한다 | "이거 해결 기록 남겨줘" |
| 금요일 | 한 주를 돌아보고 인박스를 비운다 | "주간 리뷰 해줘", "인박스 정리해줘" |

지난 일일 노트의 미완료 할 일은 날마다 옮겨 적지 않는다. `Home.md`의 "열린 할 일"에 계속 보이고, AI가 이틀 넘게 남은 항목을 알려 준다. 며칠 걸리는 일은 처음부터 프로젝트 노트에 적는다. 템플릿의 빈 `- [ ]` 줄을 채우지 않은 날은 그 줄을 지워 둔다. AI와 `sb.py`는 내용 없는 항목을 할 일로 세지 않지만, "열린 할 일" 목록에는 빈 항목으로 보일 수 있다.

이 리듬을 예약 실행으로 자동화하는 방법은 [AI와 함께 쓰기](AI와-함께-쓰기.md#자동-루틴)에 있다.

## 7. 나만의 규칙 만들기

### AGENTS.md 고치기

볼트 맨 위의 `AGENTS.md`는 AI 에이전트가 매번 먼저 읽는 볼트 규칙이다. 규칙을 바꿀 때는 이 파일만 고친다(`CLAUDE.md`, `GEMINI.md`는 이 파일을 가리키기만 한다). 규칙끼리 다르면 AI는 **사용자의 그때그때 지시 > `AGENTS.md` > `local.md` > 나의 판단 방식 노트 > 스킬 기본값** 순으로 따른다.

- **"사용자가 채우는 자리"**를 먼저 채운다. AI가 읽어도 되는 볼트 밖 폴더(예: `../업무 일지/`)와 열지 말아야 할 곳(예: `40_Resources/개인 서류/`)을 적는다. 비워 두면 볼트 밖은 아무 곳도 상시로 읽지 않는다.
- 폴더 이름이나 노트 형식을 바꾸고 싶으면 해당 절을 고친다. 폴더 이름을 바꾸면 `sb.py` 설정(`~/.second-brain/config.json`)의 `folders`도 함께 바꾼다([AI와 함께 쓰기](AI와-함께-쓰기.md#개인-설정-localmd와-configjson)). Dataview 목록의 폴더 경로도 고쳐야 하는데, 고칠 파일은 [AI와 함께 쓰기 > Obsidian 볼트 루트가 더 위에 있을 때](AI와-함께-쓰기.md#obsidian-볼트-루트가-더-위에-있을-때)의 표와 같다.

### 나의 판단 방식 노트 채우기

`30_Areas/나의 판단 방식.md`는 AI가 애매할 때 기본값으로 쓰는 내 원칙이다. 1~5번은 예시다.

- 원칙 하나에 번호 하나, 짧은 제목과 구체적인 행동 1~3줄로 쓴다.
- 좋아 보이는 말보다 내가 실제로 내린 결정, AI에게 여러 번 한 지적에서 뽑는다.
- 기준이 바뀌면 지우지 말고 줄을 긋고 날짜와 새 기준을 적는다.

AI는 이 노트로 정한 일에 `판단 근거: 판단 방식 N번`을 보고에 적는다. 그 판단이 틀렸다고 내가 말하면 해당 원칙 아래에 날짜와 함께 기록이 남는다.

### 태그는 적게

- 폴더와 `type`으로 이미 나뉘는 것은 태그로 반복하지 않는다.
- 쓰는 태그는 영역 노트(예: `30_Areas/업무.md`)의 "태그 어휘" 표에 모아 둔다. AI는 목록에 없는 태그를 새로 만들지 않고 제안만 한다.
- 지금 쓰는 태그와 개수는 `sb.py tags`로 본다. frontmatter의 `tags`에 적은 태그만 센다(본문의 `#태그`는 세지 않는다).

## 8. 자주 하는 실수와 해결

### 템플릿이나 노트에 `undefined`, 엉뚱한 날짜가 생겼다

- **원인**: Templater의 "새 파일 생성 시 실행"이 켜진 상태에서, Obsidian이 열려 있는 동안 Templater 구문이 든 파일(템플릿, 스타터 볼트)을 볼트에 복사해 넣었다. 구문이 그 자리에서 실행되어 템플릿 자체가 망가진다.
- **해결**: Obsidian을 닫는다. 설치된 스킬 폴더의 `assets/starter-vault/99_System/Templates/`에서 망가진 템플릿 파일을 볼트의 `99_System/Templates/`로 다시 복사한다. 템플릿 파일에 `<% ... %>`가 보이면 정상이다.
- **이미 만든 노트 찾기**: `sb.py lint`는 남은 `<% %>`, `[[undefined]]`, frontmatter 값 `undefined`를 "Templater 잔여 구문 또는 'undefined'"로 알려 준다. 제목이나 링크가 망가진 경우는 "제목(H1) ≠ 파일 이름"이나 "깨진 링크"로 보인다. 주간 노트의 `start`·`end`(예: `Invalid date`)와 형식은 맞지만 값이 틀린 `created`는 찾지 못할 수 있으니, 문제가 생긴 날 만든 노트는 직접 열어 값을 고친다.
- **예방**: 볼트는 Obsidian으로 열기 전에 만든다(`sb.py init`). 템플릿 폴더 밖 노트에는 Templater 구문을 쓰지 않는다.

반대로 Obsidian에서 만든 일일 노트에 `<% ... %>`가 그대로 남았다면 "새 파일 생성 시 실행"이 꺼진 것이다. 옵션을 켜거나, 그 노트를 연 상태에서 Templater의 "현재 파일의 템플릿 바꾸기"(Replace templates in the active file) 명령을 실행한다(이름은 버전에 따라 다를 수 있다).

### Dataview 표가 안 보이고 코드만 보인다

- Dataview 플러그인이 설치·활성화됐는지 확인한다(4-2).
- 편집기의 소스 모드에서는 코드가 그대로 보인다. 읽기 보기나 실시간 미리보기로 바꾼다.
- 볼트 폴더가 아니라 그 상위 폴더를 보관소로 열었다면 `FROM "00_Inbox"` 같은 경로가 맞지 않는다. 볼트 폴더 자체를 보관소로 연다(4-1). 상위 폴더를 꼭 써야 한다면 Dataview의 폴더 경로 앞에 하위 폴더 이름을 붙인다. 고칠 파일과 위치는 [AI와 함께 쓰기 > Obsidian 볼트 루트가 더 위에 있을 때](AI와-함께-쓰기.md#obsidian-볼트-루트가-더-위에-있을-때)에 모아 두었다.
- 표는 보이는데 비어 있다면 아직 해당 노트가 없는 것이다(예: `status: active`인 프로젝트가 없다).

### 같은 이름의 노트를 만들려고 했다

`sb.py new`(그리고 AI)는 볼트 어디에든 같은 이름의 노트가 있으면 만들지 않고 `이미 있습니다(덮어쓰지 않음): <경로>`를 알려 준다. 폴더가 달라도 이름이 같으면 `[[노트 이름]]` 링크가 어느 쪽을 가리키는지 헷갈리기 때문이다. Obsidian 링크는 대소문자를 가리지 않으므로 대소문자만 다른 이름(예: `home`과 `Home`)도 같은 이름으로 본다. 같은 주제라면 기존 노트에 덧붙이고, 다른 내용이라면 더 구체적인 제목을 붙인다(예: `회의 메모` → `10월 주간 회의 결정 사항`).

### 제목에 `#`, `[ ]` 같은 기호를 넣었더니 노트가 만들어지지 않는다

파일 이름에 쓸 수 없는 `/ \ : * ? " < > |`와, 파일 이름에는 쓸 수 있어도 `[[링크]]`를 깨뜨리는 `# ^ [ ]`가 든 제목은 `sb.py new`(그리고 AI)가 거부한다. 빈 제목이나 공백만 있는 제목은 `제목이 필요합니다.`로 거부한다.

```text
제목에 / \ : * ? " < > | # ^ [ ] 를 쓸 수 없습니다(파일 이름·링크가 깨짐): C# 빌드 오류
```

기호를 빼거나 글자로 바꿔 다시 부탁한다(예: `C# 빌드 오류` → `CSharp 빌드 오류`).

### 제목에 '토큰' 같은 단어를 넣었더니 노트가 만들어지지 않는다 / AI가 노트를 찾지 못한다

이름에 토큰·비번·비밀번호·password·passwd·token·secret·credential이 든 파일은 비밀정보가 들었을 수 있어 AI와 `sb.py`가 열지 않고 건너뛴다. 이런 노트는 "전에 이거 해결한 적 있나"로 다시 찾을 수 없으므로, `sb.py new`(그리고 AI)는 이런 단어가 든 제목을 처음부터 거부하고 다음처럼 알려 준다.

```text
제목에 비밀 파일로 보이는 단어가 있어 검색·점검에서 빠집니다. 다른 말로 바꾸세요(예: 토큰 → 인증): API 토큰 만료로 로그인 실패
```

다른 말로 바꿔 다시 부탁한다(예: `API 토큰 만료로 로그인 실패` → `인증 만료로 로그인 실패`). 영어 단어는 단어 단위로 본다. `token`·`tokens`·`API_token`은 걸리지만 `Tokenizer`처럼 앞뒤에 다른 영문자가 붙은 단어는 통과한다. 한국어 `토큰`·`비번`·`비밀번호`는 다른 글자와 붙어 있어도 걸린다(`토큰화`도 거부). Obsidian에서 직접 만들거나 이름을 바꾼 노트는 거부되지 않고 만들어지지만 여전히 건너뛰어진다. 그 노트로 가는 링크는 `sb.py lint`에서 깨진 링크로 나오니, Obsidian에서 이름을 바꾼다.

### 비밀번호·토큰을 노트에 적어 버렸다

1. 그 줄을 `[비밀정보 제거됨]`으로 바꾼다. 어디에 있는지 모르겠으면 `sb.py lint`가 "비밀정보로 보이는 문자열"로 찾아 준다(모든 형태를 찾지는 못한다).
2. 볼트를 git이나 클라우드로 이미 동기화했다면 파일에서 지워도 이력이나 다른 기기에 남아 있을 수 있다. 그 비밀번호나 키는 바로 바꾸거나 폐기하고 새로 발급한다.
3. 비밀정보는 비밀번호 관리자처럼 그 용도로 만든 곳에 둔다.

### 노트를 지우고 싶다

지우지 말고 `90_Archive/`로 옮긴다. 다른 노트의 링크가 깨지지 않고, 나중에 다시 찾을 수 있다. 끝난 프로젝트는 `status: done`으로 바꾸고 옮긴다. AI에게 "볼트에서 ○○ 노트를 90_Archive로 옮겨줘"라고 해도 된다(AI도 노트를 지우지 않고 옮긴다). 요청에 '볼트'를 넣어야 AI가 세컨드 브레인 일로 알아듣는다.

이름을 바꿀 때는 Obsidian 안에서 바꾸면 내부 링크 자동 업데이트 설정이 켜져 있을 때 링크도 함께 바뀐다. AI는 `sb.py backlinks "<옛 이름>"`으로 그 노트를 가리키는 링크를 찾아 볼트 안의 것만 고친다.
