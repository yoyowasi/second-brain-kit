# /inbox — 인박스 정리 (사용자와 함께)

`second-brain` 스킬의 0절(볼트 경로·`local.md`·`AGENTS.md`·날짜)을 먼저 따른다. 볼트 규칙의 원본은 볼트 `AGENTS.md`다. 아래 `sb`는 `python "$HOME/.claude/skills/second-brain/scripts/sb.py"`, `<볼트>`는 `sb where`의 vault 절대 경로다.

인자: `$ARGUMENTS` — `같이`가 있으면 3절의 "같이" 방식으로 한다.

## 1. 시작

1. `<볼트>/00_Inbox/`의 노트를 나열한다. 없으면 `인박스 비어 있음` 한 줄로 끝낸다.
2. frontmatter `type: dream`인 파일(dream 규칙 제안)과 나머지를 나눈다. dream 파일은 4절, 나머지는 2절. 둘 다 있으면 dream을 먼저 보여 준다(답을 기다리는 동안 손대지 않는다).
3. 원본 보존: 인박스 노트는 지우지 않는다. 에이전트는 볼트 git을 커밋·push하지 않는다(사용자나 Obsidian Git 같은 백업 도구 몫).

## 2. 일반 자료 하나씩

`AGENTS.md` "인박스 정리" 절차를 따르고, 다음을 더한다.

1. **읽기**: 본문이 링크뿐이면 가져와 읽는다(WebFetch). 못 가져오면 인박스에 그대로 두고 노트 끝에 `> 🤖 YYYY-MM-DD 가져오지 못함: 이유`를 단다.
2. **찾고 나서 쓰기**: `<볼트>/99_System/색인.md` → `rg -il <키워드> "<볼트>"`(`.obsidian`·`99_System` 제외) 순으로 같은 주제를 찾는다. 있으면 그 노트에 합친다. 없으면 인박스 노트 자체를 맞는 폴더로 옮기고(이동) `type`·`area`·`tags`를 채운다(second-brain 스킬 6절). `sb new`는 자료 하나를 여러 노트로 나눌 때만 쓴다.
3. **여러 노트 반영**: 자료 하나가 여러 노트(프로젝트·참고 자료·영역)를 건드리면 각각에 반영하고 서로 링크한다. 새 사실이 기존 내용과 어긋나는데 어느 쪽이 맞는지 모르면 둘 다 출처와 함께 적고 `> 충돌: 무엇이 어긋나는지`를 단다.
4. **할 일·일정**: `AGENTS.md`의 할 일 원본 규칙대로 오늘 일일 노트 `## 할 일` 또는 관련 active 프로젝트 `## 할 일`에 `- [ ] 내용 📅 YYYY-MM-DD`. `sb tasks`로 중복을 먼저 본다.
5. **원본 처리**: 기존 노트에 합쳤거나 여러 노트로 나눈 인박스 원본만 `90_Archive/`로 옮기고(이동, 삭제 아님), 반영한 노트의 `## 출처`(없으면 `## 참고`)에 `[[원래 인박스 노트 이름]]`을 단다. 그대로 옮긴 노트는 2번으로 끝. 웹 자료는 링크와 `조사일: YYYY-MM-DD`.
6. 끝나면 `sb log ingest "<자료 제목>" --source "<원본 링크 또는 [[노트]]>" --pages <고친 노트...>`.

## 3. `/inbox 같이`

자료마다 고치기 **전에** 핵심 2~3줄과 고칠 노트 목록(새로 만들 것/고칠 것)을 보여 주고 "무엇을 강조할까요?"를 묻는다. 답을 듣고 2절을 진행한다.

## 4. dream 규칙 제안 (`type: dream`)

dream은 SessionStart hook이 하루 한 번 대화에서 교정·선호를 골라 만든 **제안**이다. 사용자가 승인한 것만 규칙이 된다.

1. 제안마다 짧은 표로 보여 준다: `번호 | 종류(추가·고치기·빼기) | 위치(전역 / 프로젝트 X) | 규칙 | 근거`. 다음과 겹치거나 어긋나면 표 아래에 한 줄씩 밝힌다: 전역 `~/.claude/CLAUDE.md`(배운 규칙 포함), 볼트 `30_Areas/나의 판단 방식.md`, 해당 프로젝트 메모리.
2. "전부 / 번호(예: 1,3) / 없음"을 묻는다. 문구 수정도 받는다. **답을 들을 때까지 아무것도 고치지 않는다.**
3. **전역 반영** — 언제나 진짜 경로 `~/.claude/CLAUDE.md`를 Read/Edit로 고친다(볼트 안 사본·링크를 거치지 않는다, `sed -i`·`perl -i` 금지). `<!-- brain:start -->` ~ `<!-- brain:end -->` 안의 `# 배운 규칙 (dream)` 절만 고친다.
   - 추가: 절 끝에 `- [Lnn] 규칙`. nn은 `<!-- dream-last-id: N -->`의 N+1(두 자리, 예 L01). 쓴 뒤 그 주석을 새 번호로 갱신한다. 지운 번호는 다시 쓰지 않는다.
   - 규칙 줄이 30줄을 넘게 되면 멈추고, 합칠 줄을 사용자에게 고르게 한다.
   - 고치기·빼기: 대상 `[Lnn]` 줄을 고치거나 지운다(번호는 그대로 두거나 버린다).
4. **프로젝트 반영** — `~/.claude/projects/<slug>/memory/`에 feedback 메모리를 쓴다. 제안 머리에 `(memory: <slug>)`가 있으면 그 폴더를 그대로 쓴다. 없으면 slug는 프로젝트 실제 경로(worktree면 원래 저장소)에서 영문·숫자가 아닌 글자를 모두 `-`로 바꾼 것(예 `C:\work\shop-web` → `C--work-shop-web`, `/home/me/shop-web` → `-home-me-shop-web`). 폴더 이름만 있으면 `~/.claude/projects/`에서 `-<이름>`으로 끝나는 폴더(worktree 폴더 제외)를 찾고, 둘 이상이거나 없으면 묻는다.
   - 파일: frontmatter `name`(kebab-case)·`description`(한 줄)·`metadata: type: feedback`과 맨 위 수준 `source: dream`, 본문은 규칙 + `**Why:**` + `**How to apply:**`. 같은 폴더 `MEMORY.md`에 `- [제목](파일.md) — 한 줄` 포인터를 더한다. 같은 주제 메모리가 있으면 새로 만들지 말고 고친다.
   - 고치기·빼기: `~/.claude`는 git 밖이라 되돌릴 수 없다. 고치거나 빼기 전에 원본을 `~/.second-brain/state/removed-memory/<slug>/YYYY-MM-DD-<파일 이름>`으로 복사한다. 빼기는 지우지 말고 그곳으로 옮긴 뒤 `MEMORY.md` 포인터만 뺀다. 대상에 `source: dream`이 없으면(사용자·다른 세션이 쓴 메모리) 표 아래에 그 description과 본문 첫 줄을 보여 주고 그 번호만 따로 한 번 더 확인받는다.
5. **처리 결과**: dream 파일 끝에 `## 처리 결과 (YYYY-MM-DD)` — `반영: 1, 3 · 거절: 2 · 보류: 4`. 보류가 없으면 파일을 `90_Archive/`로 옮기고, 보류가 있으면 인박스에 둔다. `sb log ingest "dream 제안 <파일 날짜>" --source "[[파일 이름]]" --note "반영 1,3 · 거절 2 · 보류 4"`.
6. 줄을 덧붙일 때 파일 끝 줄바꿈을 확인한다(없으면 새 줄이 앞 줄에 붙고 패턴이 어긋난다). 고친 뒤 그 파일을 다시 읽어 의도한 줄만 바뀌었는지 본다.

## 5. 보고

결론부터, 표로: `원래 이름 → 위치(이동·합침·남김과 이유)`, 반영한 규칙(`[Lnn]` 또는 메모리 경로). 고친 볼트 노트는 `sb lint "<절대 경로>" ...`로 점검하고 결과 줄을 적는다.
