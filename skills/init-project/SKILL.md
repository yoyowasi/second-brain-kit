# /init-project — 저장소 노트 만들기·갱신

대상 경로: `$ARGUMENTS` (비어 있으면 지금 작업 폴더).

혼자 도는 작업이라 중간에 물을 수 없다. 판단이 서지 않으면(대상이 코드 프로젝트가 아님, 경로 없음, 같은 이름 노트가 다른 저장소를 가리킴 등) **아무것도 쓰지 말고** `확인 필요: <이유>`만 돌려준다.

## 0. 준비

- `sb` = `python "$HOME/.claude/skills/second-brain/scripts/sb.py"`. `sb where`로 볼트(`<볼트>`)를, `sb today`로 날짜를 얻는다. `~/.second-brain/local.md`와 `<볼트>/AGENTS.md`를 읽는다(보안 금지 목록, 회사 폴더, 프로젝트 연결 표).
- 볼트 파일은 절대 경로로 다룬다. 프로젝트 폴더는 **읽기만** 한다(파일 수정·git 쓰기 명령 금지).

## 1. 읽을 것 (있는 것만, 큰 파일은 앞부분만)

README, CLAUDE.md·AGENTS.md, CHANGELOG, `docs/` 목차, 패키지 설정(`package.json`·`pom.xml`·`build.gradle`·`pyproject.toml` 등 — 이름·스크립트·주요 의존성만), `git log --oneline -40`, `git status --short`, `git remote -v`, 진입점·라우팅·데이터 흐름(라우터, main/app 파일, API 계층)을 훑는다. Claude 메모리 `~/.claude/projects/<slug>/memory/MEMORY.md`도 본다(slug = 실제 경로에서 영문·숫자가 아닌 글자를 `-`로 바꾼 것, 예 `C:\work\shop-web` → `C--work-shop-web`, `/home/me/shop-web` → `-home-me-shop-web`).

**열지 않는다**: `.env*`, `application*.yml`·`*.properties`의 접속 정보, `*.pem`·`*.key`, 이름에 token·secret·password·토큰·비번이 든 파일, `node_modules`·`dist`·`build`. 노트에 비밀값·접속 문자열·개인정보를 쓰지 않는다.

## 2. 노트 위치와 틀

- 위치: `<볼트>/40_Resources/저장소/<저장소 폴더 이름>.md`. 없으면 `sb new repo "<이름>"`으로 만든다(같은 이름이 있으면 거부된다 — 그 노트가 같은 저장소면 3절, 아니면 `확인 필요`).
- frontmatter: `type: repo`. `local.md` "저장소 노트" 절의 회사 프로젝트 폴더 아래면 `area: "[[업무]]"`, 그 밖이면 `area: "[[학습]]"`(`local.md`에 기준이 없거나 볼트에 그 영역 노트가 없으면 비워 두고 4절 보고의 '확인 못 한 칸'에 적는다). `tags`는 `local.md` 태그 어휘에서만 고른다: 회사 저장소는 주제·도메인 태그, 개인 저장소는 학습 쪽 태그만(업무 화면에 섞이지 않게). 맞는 것이 없으면 `[]`.
- 본문 틀(이 순서, 제목 그대로):
  - `# 이름` 다음 줄 `> 한 줄 요약`
  - `## 개요` — 무엇을 왜 하는 저장소인지 2~4줄
  - `## 위치` — 로컬 경로, 원격 저장소 URL(토큰이 들어 있으면 지운다), 배포 주소(문서에 있을 때만)
  - `## 스택` — 언어·프레임워크·주요 라이브러리와 버전(선언과 lock이 다르면 둘 다)
  - `## 기능` — 10줄 이내
  - `## 구조와 흐름` — 3~7줄. 무엇이 무엇을 부르는지와 그 이유(예: 화면 → API → DB)
  - `## 현재 상태` — `YYYY-MM-DD 기준:` 브랜치, 미커밋 변경 수, 최근 작업 흐름
  - `## 주요 결정` — `- (YYYY-MM-DD) 결정 — 이유` (커밋·문서·메모리에서 확인한 것만)
  - `## 다음 할 일` — `- [ ] ...`. 단 이 저장소의 일이 `20_Projects/`의 active 프로젝트(`local.md` 프로젝트 연결 표)에 이미 있으면 여기 복사하지 말고 `→ [[프로젝트]]` 한 줄만 둔다(할 일 원본은 한 곳).
  - `## 관련` — 영역, 관련 프로젝트, 관련 해결 기록·참고 자료 `[[링크]]`(최소 하나)
- 함수·파일 단위 설명과 API 목록은 넣지 않는다(금방 낡는다). Claude 작업 규칙(feedback 메모리)도 옮기지 않는다.
- 확인하지 못한 칸은 `확인 못 함`이라고 적는다. 채울 근거가 거의 없으면 노트를 만들지 말고 `확인 필요`로 돌려준다(빈 노트 금지).

## 3. 이미 노트가 있으면

다시 읽고 고쳐 쓴다. `## 주요 결정`과 `## 다음 할 일`은 **지우지 않고 덧붙인다**. 끝난 할 일만 근거 커밋과 함께 `- [x] ... (abc1234)`로 바꾼다. 사용자가 쓴 다른 줄은 보존한다.

## 4. 마무리

1. `sb lint "<노트 절대 경로>"` — 이번에 생긴 문제는 0건이 될 때까지 고친다.
2. `sb index --quiet` (색인 갱신), `sb log ingest "<저장소 이름> 저장소 노트" --source "<프로젝트 경로>" --pages "<노트 이름>"`.
3. 커밋·push하지 않는다(볼트 git은 사용자나 Obsidian Git 같은 백업 도구 몫).
4. 3~6줄로 돌려준다: 노트 절대 경로, 생성/갱신, 확인 못 한 칸, 연결한 노트, lint 결과.
