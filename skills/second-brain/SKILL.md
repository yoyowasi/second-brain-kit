# Second Brain

보조 도구 `scripts/sb.py`(Python 3.9+)가 날짜·템플릿 치환·중복 확인·점검을 맡는다. 아래 `sb <명령>`은 `python "<이 스킬 폴더>/scripts/sb.py" <명령>`이다.

## 0. 시작할 때 (매번)

1. `sb where`로 볼트 경로를 확인한다. 설정이 없으면 1절로 간다.
2. `sb where`가 알려 주는 `local.md`(기본 `~/.second-brain/local.md`)가 있으면 읽는다. 이 사용자 볼트만의 설정(태그 어휘, 기록 정책, 프로젝트 연결, 더 읽어도 되는 폴더)이다.
3. 볼트의 `AGENTS.md`를 읽는다. 볼트 규칙의 **단일 기준**이다. 이 스킬은 규칙을 복사하지 않고 지키는 방법만 더한다. 우선순위: 사용자의 그때그때 지시 > `AGENTS.md` > `local.md` > `나의 판단 방식` 노트 > 이 스킬.
4. 방식·우선순위가 애매하면 볼트의 `30_Areas/나의 판단 방식.md`(있으면)를 기본값으로 쓴다. 그 원칙이 이번 상황에 실제로 해당할 때만 근거로 든다.
5. 날짜는 `sb today`로 얻는다(오늘·요일·ISO 주차·월~일·일일/주간 노트 경로). 요일 이름("금요일까지")은 `sb today --date <후보>`로 요일을 확인한다. 머리로 계산하지 않는다.
6. 다른 프로젝트 폴더에서 일할 때는 볼트 파일을 **절대 경로**로 다룬다. 상대 경로를 쓰면 지금 작업 폴더에 노트가 잘못 생긴다.
7. 쓸 일이 생길 것 같으면(조건부 계획이라도) [references/capture.md](references/capture.md)를 먼저 읽는다.
8. **자동으로 쌓이는 층**(Claude Code hook을 설치했을 때 — 키트 README "자동 기록"): 세션 일지 `10_Daily/Journal/YYYY-MM-DD 세션.md`, dream 규칙 제안 `00_Inbox/*dream*.md`(`type: dream`), 색인 `99_System/색인.md`. 읽기만 하고 손으로 고치지 않는다. dream 제안은 `/inbox`에서만 처리한다. 세션 맥락에 `[brain] ...` 줄이 있으면 그 지시대로 첫 답 끝에 한 줄로 제안한다.

## 1. 볼트가 없을 때: 만들기·연결하기

- "세컨드 브레인 만들어줘": 만들 위치를 묻는다(기본 제안 `~/Documents/SecondBrain`, Windows는 짧은 경로 권장). `sb init "<폴더>"`로 스타터 볼트를 만든다(노트가 이미 있는 폴더는 거부된다). 이어서 사용자가 할 일을 안내한다: Obsidian에서 그 폴더를 보관소로 열기 → Dataview·Templater 켜기 → Templater 템플릿 폴더 `99_System/Templates`. 자세한 안내는 저장소의 `docs/세컨드-브레인-만들기.md`.
- Obsidian이 **열기 전에** 만든다. Templater가 새 파일 생성 시 실행되도록 켜진 볼트에 템플릿 파일을 넣으면 구문이 실행돼 망가진다.
- 기존 볼트가 있으면 `sb setup "<폴더>"`. 경고(AGENTS.md·템플릿 없음)가 나오면 스타터 파일을 보여 주고, 볼트에 맞게 고쳐 넣을지 사용자에게 묻는다.

## 2. 경계

- **노트 쓰기는 볼트 폴더 안에서만.** 예외: `local.md` 기록 정책이 정한 에이전트 메모리(사실을 확인한 저장소의 프로젝트 메모리)에는 쓴다. 메모리에는 볼트 노트의 절대 경로를 적는다.
- **볼트 밖 읽기**: 볼트 상위의 노트 원본 폴더는 `AGENTS.md`·`local.md`가 허용하고 사용자가 지정할 때만 읽는다. 사용자가 채팅에서 경로를 주며 읽으라고 하면 읽는다. 사용자가 지금 작업 중이라고 밝힌 코드 저장소는 그 프로젝트 지침대로 읽기 전용으로 볼 수 있다. 어느 경우든 아래 금지 목록은 예외 없다.
- **열지 않는다:** `AGENTS.md`·`local.md`가 금지한 경로, 이름에 토큰·비번·비밀번호·password·passwd·token·secret·credential이 든 파일·폴더, `.env`·`.pem`·`.key`로 끝나는 파일, `.obsidian/`. 볼트 상위 폴더 전체를 검색하지 않는다(비밀 파일이 걸린다). 같은 이유로 노트 제목에도 이 단어를 쓰지 않는다(`sb new`가 거부한다).
- **비밀정보를 쓰지 않는다.** 볼트가 git·클라우드로 동기화되면 쓴 내용은 그대로 밖으로 나간다. 쓰기 전에 capture.md "비밀정보 거르기"로 초안을 확인하고, 걸리면 `[비밀정보 제거됨]`으로 바꾸고 알린다. 볼트의 git commit·push는 사용자가 요청할 때만.
- **지우지 않는다.** 필요 없어진 노트는 `90_Archive/`로 옮긴다. 이름을 바꾸면 `sb backlinks "<옛 이름>"`으로 찾아 볼트 안 링크만 고치고 밖은 보고만 한다.
- **덮어쓰지 않는다.** 새 노트는 `sb new`로 만든다(볼트 어디든 같은 이름이 있으면 대소문자 무시하고 거부). 기존 노트는 Edit로 해당 절만 고치고, 다른 사람이 쓴 줄은 보존한다. 해결 기록에 사례를 더할 때는 capture.md의 "사례 덧붙이기" 형식(맨 끝 `## 사례 N`)만 쓴다.
- **고치기 직전에 다시 읽는다.** 읽은 뒤 파일이 바뀌었으면(Obsidian·다른 세션·루틴) 편집만 다시 하지 말고 판단(중복 확인, 줄 상태, 보고문)을 처음부터 다시 한다. 수정 시각이 몇 분 이내면 다른 쪽이 쓰는 중일 수 있으니 보고에 알린다. Edit 위치는 줄 번호가 아니라 고유한 문자열로 잡는다.
- **Templater 구문(퍼센트 꺾쇠)을 노트에 남기지 않는다.** `sb new`/`sb render`가 실제 값으로 바꾼다. `updated`는 쓰지 않는다(플러그인 몫). `created`는 `YYYY-MM-DDTHH:mm`.
- 파일은 UTF-8(BOM 없음)·LF로, Write/Edit 도구로 쓴다. Windows PowerShell의 `Set-Content`/`Out-File`은 인코딩이 바뀌므로 쓰지 않는다.

- 찾기·"확인만" 요청은 읽기 전용이다. 볼트에 없던 사실을 이번에 새로 확인했을 때만 `local.md` 기록 정책을 따른다. 볼트 기록을 다시 확인한 것은 새 사실이 아니다. 정책이 없으면 작업 끝에 "해결 기록으로 남길까요?"라고 한 줄 제안한다.
- 해결 기록이 아닌 종합·비교·분석·웹 조사 답은 끝에 "브레인에 남길까요?"를 한 줄로 묻는다(단순 사실 확인·코드 작업 보고·이미 볼트에 있는 내용이면 묻지 않는다).
- 기록할 대상(화면·파일·환경)이 정해지지 않았거나, 찾은 증거가 사용자의 말과 어긋나면 **쓰기 전에** 후보 2~3개와 증거를 보여 주고 한 번 묻는다. 쓰고 나서 묻지 않는다.

## 4. 찾기와 답하기

0. 먼저 `99_System/색인.md`(자동 생성 목록: 폴더별 노트 이름·태그·한 줄 요약)를 읽고 열 노트를 고른다. 지난 작업 흐름·날짜가 필요하면 `10_Daily/Journal/`의 세션 일지도 본다.
1. 키워드 2~4개를 잡고 볼트 안에서만 찾는다(Grep 도구 또는 `rg -F -i`, `.obsidian`·`99_System` 제외). 식별자 키와 함께 증상 구절 키도 쓰고, 파일 이름 검색도 함께 한다. 검색 키를 고르는 법과 우선순위는 [references/search.md](references/search.md).
2. 걸린 파일은 일치 줄 전후만 읽고, 필요한 `[[링크]]`를 한 단계만 따라간다.
3. 결론부터 답하고 근거 노트를 `[[노트 이름]]`으로 밝힌다(다른 프로젝트 세션이면 절대 경로도). "기록이 있다"와 "해결됐다"를 구분한다(원인만 확인했거나 외부 수정을 기다리는 기록이면 그렇게 말한다).
4. 노트의 `확인:`/`추정:`과 검증 범위를 그대로 옮긴다. 노트를 옮겨 적을 때 조건·범위를 좁히거나 넓히지 않는다. 노트는 그 시점의 기록이라 지금 코드·버전과 다를 수 있다고 구분하고, 지금 다시 확인하지 않은 것은 "오늘 다시 확인하지 않음"이라고 적는다.
5. 같은 증상인데 원인이 다른 노트가 걸리면 빼지 말고 "대상이 X이면 이 노트, Y이면 저 노트"로 갈래를 보여 준다.
6. 볼트에 없으면 "볼트에 없음"이라고 먼저 말하고 일반 지식으로 보충한다.

## 5. 오늘 노트 · 인박스 · 프로젝트에 적기

- 오늘 노트가 없으면 `sb new daily`. 있으면 템플릿에 있는 절 끝에 덧붙인다: 그날 끝낼 일은 `## 할 일`, 한 일은 기록 절(`## 기록`·`## 업무 기록` 등), 생각은 `## 메모 · 떠오른 생각`, 배운 것·만든 해결 기록 링크는 `## 오늘 배운 것`. 그 절에 템플릿의 빈 `- [ ] ` 또는 `- ` 줄이 있으면 새 줄을 더하지 말고 그 줄을 채운다.
- **할 일의 원본은 한 곳.** 오늘 끝낼 일은 오늘 노트 `## 할 일`에 `- [ ] 내용`. 마감이 오늘이 아니거나 며칠 이어지는 일은 관련 active 프로젝트 `## 할 일`에 `- [ ] 내용 📅 YYYY-MM-DD`(맞는 프로젝트가 없으면 오늘 노트에 📅와 함께). 미래 날짜의 일일 노트는 미리 만들지 않는다. 보고에 해석한 마감 날짜를 적는다. 같은 할 일을 두 곳에 복사하지 않는다(`sb tasks`로 먼저 확인).
- 분류가 애매하면 `sb new inbox "<제목>"`(링크 없어도 된다).
- 새 프로젝트는 `sb new project "<이름>"` 뒤 `area: "[[영역]]"`·`due`와 `## 목표 · 완료 조건`을 채운다.
- 자동 루틴이 쓰는 블록(`🤖`로 시작하는 줄, `<!-- 진행 중: ... -->`, 루틴이 교체하는 절)은 `local.md`·`99_System/Routines/`에서 확인하고 중복으로 만들지 않는다. 내가 쓴 내용을 루틴이 다시 후보로 적을 수 있으면 보고에 알린다.

## 6. 반복 작업 보조

절차는 `AGENTS.md` "반복 작업"을 따르고, 틀리기 쉬운 부분을 도구로 메운다.

- **오늘 노트**: `sb today` → 없으면 `sb new daily`. 이틀 넘은 미완료는 `sb tasks --older 2`로 찾아 알리기만 한다(복사하지 않는다).
- **주간 리뷰**: `sb today`의 `iso_week`·`start`·`end`를 쓴다. 노트가 이미 있으면 비어 있는 절만 채운다. 방치 프로젝트는 `sb stale`(파일 수정 시각 기준, 상태는 사용자가 정한다).
- **인박스 정리**: 노트를 지우고 새로 만들지 말고 옮긴(move) 뒤 frontmatter를 고친다. 여러 노트로 나누거나 기존 노트에 합친 원본은 `90_Archive/`로. 결과는 "원래 이름 → 위치" 표.
- **노트 정제**: 생각 하나당 `sb new note "<한 문장 주장>"`, 본문 3~10줄, 출처 링크 필수, 추측은 `> 추측:`.
- **태그**: 새 태그를 만들기 전에 `sb tags`로 쓰던 어휘를 확인한다(`local.md`에 어휘가 있으면 그것만).
- **점검**: `sb index` → `sb lint`(볼트 전체) → `sb tasks`·`sb stale` 결과로 AGENTS.md "점검" 2번 내용 점검. 볼트 안 링크·형식 문제만 고치고, 상태·사실 판단은 목록으로. 끝에 웹으로 채울 빈칸·다음 질문 3개 이내, `sb log lint "점검" --pages <고친 노트...>`.
- **작업 기록**: 볼트에 쓴 일(ingest·query·lint)은 `sb log`로 남긴다. 그냥 찾아서 답만 한 질문은 남기지 않는다.

## 7. 마무리와 보고

1. **검증은 실제 볼트 파일로.** 쓴 뒤 그 파일들을 다시 읽어 의도한 줄만 바뀌었는지 보고, `sb lint "<절대 경로>" ...`를 돌린다. 출력의 `점검(지정한 파일) N개`가 바꾼 파일 수와 맞는지 확인한다. 사본·시뮬레이션 점검은 검증이 아니다. 날짜 링크(`[[YYYY-MM-DD]]`)는 일일·주간 노트에서는 lint가 건너뛰므로 파일 존재로 따로 확인한다.
2. **바꾼 파일 안의 기존 문제**: 기본은 고치지 않고 목록으로 남긴다. `local.md`·판단 방식이 "같은 파일 안 문제는 같이 고친다"고 정했으면 lint가 잡은 문제는 고치고 "원래 있던 문제 수정"으로 따로 밝힌다. 바꾸지 않은 파일의 문제는 언제나 목록으로만.
3. **보고문은 쓰기·lint를 마친 뒤의 실제 상태로** 쓴다. 미리 써 둔 문장을 쓰지 않는다. 결론부터, 표로: `파일(절대 경로) | 한 일(생성/추가/이동) | 연결한 노트`. 읽기만 했으면 `볼트 변경: 없음(읽기 전용)`.
4. 확인한 것과 추정, 검증 범위를 구분한다. 쿼리·설정을 읽고 추론한 결과(예: "Home 목록에 보인다")는 "정적 추정"으로 적는다.
5. 중복 확인 결과(찾은 키, 걸린 노트, 제외한 노트와 이유)를 한 줄로 적는다.
6. 판단 방식을 써서 정했으면 보고 끝에 `판단 근거: 판단 방식 N번(원칙)`. 범위 밖에서 본 문제는 "범위 밖 발견(고치지 않음)" 목록으로.
