# 볼트에서 찾기

"볼트 기준으로 X", "전에 해결한 적 있나", 그리고 기록 전 중복 확인에 쓴다.

## 범위

- 볼트 폴더 안에서만 찾는다. 상위 폴더(Obsidian 볼트 루트가 더 위일 수 있다)를 통째로 검색하지 않는다 — 비밀 파일이 함께 걸린다.
- 제외: `.obsidian/`, `.git/`, `.trash/`, `99_System/`(템플릿이 `type: fix` 등으로 같이 걸린다), `local.md`·`AGENTS.md`의 금지 경로.
- 예: `rg -F -i -l "<키워드>" "<볼트>" -g "!.obsidian/**" -g "!99_System/**"` (Claude Code에서는 Grep 도구에 같은 경로·glob을 준다)

## 우선순위

1. `40_Resources/해결 기록` — 증상 → 원인 → 변경 → 검증
2. `40_Resources/` 나머지(참고 자료) — 대응표, 설정값, 개념
3. `20_Projects` → `90_Archive` — 확정된 사실·진행 기록
4. `10_Daily`(최근부터) → `10_Daily/Weekly`
5. `30_Areas`, `50_Notes`

## 검색 키 고르기

- **식별자와 증상을 함께**: 화면·함수·클래스·테이블·프로시저 이름, 설정 키, 오류 메시지의 가장 특이한 토큰(따옴표·경로·숫자는 뺀다)으로 찾고, 대상이 정해지지 않았으면 증상 구절("빈칸", "비어", "표시되지 않는다")로도 찾는다. 같은 증상인데 원인이 다른 노트를 놓치지 않기 위해서다.
- **표기 흔들림**: 같은 이름이 `ORDER_LIST`, `orderList`, `OrderList`로 섞여 있을 수 있다. `-i`와 토큰 사이 `_?`로 한 번에 찾는다: `rg -i "order_?list"`.
- **줄여 적은 이름**: 전체 이름이 0건이면 접미사를 떼고 앞부분으로 다시 찾는다.
- **한국어 증상**: "0건"·"오류"처럼 짧은 토큰은 엉뚱한 줄에 걸린다(예: "10건"). "빈칸으로 표시", "표시되지 않는다", "오류가 난다"처럼 명사 2~3개나 제목형 구절로 찾는다.
- **파일 이름 검색**: 해결 기록·영구 노트는 파일 이름이 곧 증상·주장이다. `rg --files "<볼트>/40_Resources" | rg -i "<키워드>"`.
- 버전 문자열은 고정 문자열로: `rg -F "2.4.1"`.

## 읽고 따라가기

- 걸린 파일은 일치 줄 전후만 읽는다. frontmatter의 `type`·`tags`(`미결`이면 미해결로 보고)·`created`를 본다.
- `## 출처`의 `[[YYYY-MM-DD]]`(그날 일일 노트)와 관련 프로젝트 링크를 한 단계만 따라간다.
- 볼트 밖 원본 링크(`[[다른폴더/...]]`)는 `local.md`가 허용하고 사용자가 원본 확인을 원할 때만 연다.

## 답할 때

- 근거 노트를 `[[노트 이름]]`으로 밝힌다. 다른 프로젝트 세션이면 절대 경로도 적는다.
- 노트에 적힌 `확인:`/`추정:`과 검증 범위를 그대로 옮긴다. 다른 기록을 옮겨 적은 노트의 "확인"은 "원본 기록 기준"이지 다시 실행한 결과가 아니다.
- 노트가 가정한 버전·환경과 지금 작업 대상이 다르면 그 차이를 말한다. 지금 다시 확인하지 않은 사실(예: 최신 버전)은 "오늘 다시 확인하지 않음"이라고 적는다.
- "기록이 있다"와 "해결됐다"를 구분한다. 원인만 확인했거나 외부 수정을 기다리는 기록이면 그렇게 말한다.
- 노트의 조건·범위를 옮길 때 좁히거나 넓히지 않는다(예: 노트가 "합계·평균·개수"라고 했으면 "합계"로 줄이지 않는다).
- 같은 증상에 원인이 다른 노트가 여럿이면 빼지 말고 "대상이 X이면 이 노트, Y이면 저 노트"로 갈래를 보여 주고, 사용자가 고를 수 있게 질문을 좁힌다.
- 볼트에 없으면 "볼트에 없음"이라고 먼저 말한다.
